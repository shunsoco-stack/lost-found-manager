# 忘れ物・落とし物管理 ― おかえりカウンター

## 概要

商業施設・ホテル・スポーツ施設などの受付で、持ち主不明の拾得物を記録する端末内完結の業務アプリです。**デモ用の架空データです。**

## 主な機能

### 拾得物の登録

年月ごとに受付番号を自動採番し、拾得日時・場所・拾得者・権利放棄・分類・複数色・特徴・保管場所を記録します。写真は6枚まで、長辺1600pxに縮小して保存します。現金は金額、カードは枚数のみ記録し、財布・電子機器・鍵などを貴重品として表示します。一覧は状態・分類・色・期間・特徴で絞り込み、BOM付きCSVに書き出せます。

### 特徴検索と照合

分類30点、色20点、日付20点、場所15点、特徴語15点で候補を並べ、一致理由を表示します。日付が範囲から2日以内なら10点、同じフロアなら5点、特徴語は一致した語の割合で加点します。問い合わせの日時・名前（任意）・連絡方法・内容・結果を記録し、「該当なし」の問い合わせ後に登録された保管中の品が65点以上で一致すると「該当の可能性あり」を画面内に通知します。

### 本人確認と返却の記録

確認書類の種類、本人が答えた特徴、一致確認、受取人、受取日時、スタッフ、画面上の署名を保存します。書類番号は記録しません。返却記録への未知の項目追加も拒否します。返却済み・引き渡し済み・処分済みの二重処理は禁止します。

### 保管期限と警察への引き渡しリスト

期限切れと3日以内の品を表示し、選択した品をA4縦・1ページ5件のリストにします。施設名・担当者・引き渡し日・受領印欄付きで印刷でき、CSVも書き出せます。印刷と引き渡し完了の記録は別操作です。履歴は当時の内容を保持し再印刷できます。施設処分設定の期限切れ品は処分済みとして記録でき、貴重品の施設処分は拒否します。

## 日時と保管期限の扱い

日本時間を基準に、初回起動とリセット時に過去約6週間のデータを生成します。日付は `YYYY-MM-DD`、時刻は `HH:MM`、保存日時は `YYYY-MM-DDTHH:MM` です。localStorageと現在時刻はクライアントのマウント後に読みます。

拾得は10:00〜21:00中心で、閉館後の清掃による拾得も含みます。0時台には今日の拾得は0件となり、昨日の記録が表示されます。保存済みの日付は起動のたびに動かしません。

期限は拾得日＋分類ごとの日数です。残り0〜3日が「3日以内」、期限日の翌日から「期限切れ」です。月末・年末・うるう年に対応します。警察へ引き渡す分類は初期値7日、傘・衣類はデモ用に14日で施設処分する設定です。設定変更は保管中の品にも適用されます。

## 注意

**期限・手続きは遺失物法の運用を参考にした目安です。実際の運用は各施設・警察署で確認してください。** 処分設定が法的な処分権限を与えるものではありません。

単一端末・単一タブでの利用を想定しています。実運用向けの認証・権限管理はありません。ブラウザの保存データ削除や端末故障に備え、JSONバックアップをご利用ください。氏名・連絡先・署名を含むため、保存先にはご注意ください。

## 既存作品との違い

| 作品                     | 本作との違い                                                                 |
| ------------------------ | ---------------------------------------------------------------------------- |
| 備品・機材の貸出返却台帳 | 持ち主不明の拾得物を扱い、貸出・返却予定日・QRはありません。                 |
| 問い合わせ管理システム   | 一般的な案件管理ではなく、拾得物との特徴照合のために問い合わせを記録します。 |
| 設備・備品管理システム   | 資産・設備・在庫を管理せず、拾得から返却・引き渡し・処分を扱います。         |

## 画面一覧

| パス                 | 画面                                 |
| -------------------- | ------------------------------------ |
| `/`                  | 今日の受付・貴重品・期限・照合通知   |
| `/items`             | 状態別一覧・絞り込み・CSV            |
| `/items/new`         | 拾得物の登録                         |
| `/items/[id]`        | 詳細・編集・写真・履歴               |
| `/inquiries`         | 問い合わせと特徴照合                 |
| `/items/[id]/return` | 本人確認・署名・返却                 |
| `/handover`          | 期限管理・引き渡し・印刷・履歴       |
| `/settings`          | 施設・場所・スタッフ・分類ごとの期限 |
| `/backup`            | 写真・署名を含むJSONの保存・復元     |
| `/about`             | デモの説明・既定データへのリセット   |

静的書き出しでは未知のIDのHTMLを事前生成できないため、同じ画面を `/items/detail?id=...` と `/items/return?id=...` で提供します。`npm run build:static` ではアプリ内リンクがこの形式に切り替わり、シードにない新規登録IDも開けます。通常ビルドでは `/items/[id]` 形式です。いずれもクライアントのlocalStorageから記録を読みます。

## データの保存先

| データ                                 | 保存先                               |
| -------------------------------------- | ------------------------------------ |
| 拾得物・問い合わせ・設定・引き渡し履歴 | localStorage `lfm:v1`                |
| 縮小写真・署名                         | IndexedDB `lfm-photos` / `images`    |
| オフライン用の公開画面・静的アセット   | Service Worker `lfm-shell-v1`        |
| バックアップ                           | ダウンロードしたJSON（画像はbase64） |

壊れた保存データは既定データへ戻して通知します。バックアップは検証と件数確認後に復元し、不正な形式・参照欠落・状態や署名項目を拒否します。外部API・警察連携・メール・SMS・サーバー保存・AI画像認識はありません。

Service Workerは本番のみ登録します。訪問済み画面と静的アセットをキャッシュし、未訪問の画面や更新後の初回表示には接続が必要な場合があります。

## ローカル起動方法

Node.js 24以降を使用します。すべて `lost-found-manager` フォルダ直下で実行してください。

```sh
npm install
npm run dev
```

http://localhost:3000 を開きます。本番確認は次のとおりです。

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm start
```

`npm run build:static` は `out/` に静的出力します。通常起動に戻す際は `npm run build` を再実行してください。`turbopack.root: process.cwd()` は維持してください。

Windowsでの静的書き出しでは、Next.jsが出力する画面遷移用ファイルに、ブラウザが要求するパスの別名を生成します。マニフェストも静的に出力します。

純粋関数のテストは300件です。問い合わせ文の独自性・氏名の重複、紛失申告から問い合わせまでの時間、照合期間、営業時間、拾得後の登録、今日の照合候補を検証します。深夜・土日・年末年始を含む日時で未来の記録がないこと、処分期限、月別採番、不正な保存データの拒否も確認します。

`scripts/verify-browser.mjs` は既存のPlaywrightを使う任意のブラウザ検証です。パッケージの追加や画像撮影は行いません。`PLAYWRIGHT_MODULE` に既存の `playwright/index.mjs` の絶対パス、`TEST_BASE_URL` に起動中の本番サーバーURLを設定して実行します。既定URLは `http://localhost:3018` です。`TEST_STATIC=1` の場合は `out/` を配信して静的書き出しを検証します。375px幅の全画面、写真付き登録、照合、署名返却、引き渡し、バックアップ復元とブラウザのコンソールエラーを確認します。

```sh
npx --yes prettier@3 --write "src/**/*.{ts,tsx,css}" "tests/**/*.js" README.md
```

## デモデータについて

施設「（架空）みなとみらいテラス 2F総合案内」、拾得場所10か所、スタッフ5名、拾得物60件、問い合わせ24件です。保管中18件（期限切れ4件・3日以内3件）、返却済み28件、警察引き渡し済み9件（1回分）、処分済み5件を含みます。

特徴と来館者の問い合わせ文はそれぞれ個別に用意し、問い合わせ者名は重複させず、返却時の受取人とも一致させています。時刻・場所は日付を種とする乱数で選びます。拾得は10:00〜21:00（シネマは22:30まで）、登録は3〜60分後です。問い合わせは紛失申告から数時間〜3日後、照合期間は申告に応じた1〜3日で、折り返し待ち・後日来館予定も記録します。今日の問い合わせ1件には保管中の財布の候補があります。深夜分は時間外受付として扱い、00:00ちょうどは未来の記録を避けるため前日分にします。別に問い合わせ後の登録による自動通知の例も残しています。

週末には拾得が増える重みを付け、シード内の雨の日は傘が多くなるようにしています。すべて架空で、画像はcanvasで描いたサンプルです。色・角度・背景を変え、画像内に「サンプル画像」と明記します。日付は開いた日からの相対です。保存済みデータは変更されないため、新しいシードはデモデータの再生成で反映してください。
